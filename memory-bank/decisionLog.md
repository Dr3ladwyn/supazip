# Decision Log

| Date | Decision | Rationale |
|------|----------|-----------|
| 2026-06-05 | Use `Box<dyn Read>` / `Box<dyn WriteSeek>` in `ArchiveFormat`, not `<R: Read, W: Write + Seek>` generics. | Object safety is required for the `BACKENDS: LazyLock<HashMap<&str, &dyn ArchiveFormat>>` registry. Documented in `traits.rs` design note. |
| 2026-06-05 | Enable `zip/chrono` feature and use `TryFrom<zip::DateTime> for chrono::NaiveDateTime`. | `zip 2.4.2` removed `try_to_datetime`. Direct `chrono` conversion is the supported path. |
| 2026-06-05 | Replace `ZipArchive::set_password` with `by_index_decrypt` / `by_name_decrypt`. | `set_password` was removed in `zip 2.x`; per-entry decrypt API is the current idiom. |
| 2026-06-05 | Use `SevenZWriter::set_content_methods([Aes256Sha256 + LZMA2])` for encrypted 7z create, instead of returning `Unsupported`. | The library **does** support it; the original `let _pwd = password` was a real bug, not an upstream limitation. |
| 2026-06-05 | Keep `extract` buffered in core, but `list` and `test` stream. | `sevenz-rust 0.6.1` and `zip 2.4.2` both need a `Read + Seek` input internally; streaming the outer pass saves no copies. Code comment in `formats/zip.rs` and `formats/sevenz.rs` explains. |
| 2026-06-05 | Report 7z `ArchiveEntry::encrypted` based on the entry's `has_crc` / folder-coder state, not hard-coded `false`. | Plaintext 7z entries expose this through the coder type; the previous hard-coded `false` was a real bug. |
| 2026-06-05 | `git init` the repo root before Phase 4 commits. | The directory was never a git repo; the brief asks for logical chunks of commits and a final report. |
| 2026-06-05 | GUI build is intentionally left out of `cargo build` / `cargo test` runs in CI / verification. | egui 0.34.1 needs rustc 1.92; local toolchain is 1.88.0. This is a toolchain issue, not a code issue. |
| 2026-06-06 | Defer async trait for backends past 1.0. | Backends stay synchronous through 0.2 → 1.0. Native AFIT is the preferred path when it stabilises; the question is re-opened only on real demand (network archives, very large streaming inputs). |
| 2026-06-06 | Defer light theme to 1.1. | 1.0 keeps the dark-only design system from `DESIGN.md`. Light theme work begins after 1.0 based on real user feedback, not assumptions. |
| 2026-08-17 | GUI consumes design tokens v2 at runtime (`Style::from_tokens`); `settings.theme` is Dark / Light / System. | Tokens 2.0 already landed. Light is a settings choice; default stays Dark so 1.0 installs do not flip. JetBrains Mono embeds only when the OFL TTF is present under `assets/fonts/`. Toolbar icons are egui strokes, not emoji/PNG. |
| 2026-06-06 | Use pure-Rust tar backend stack: `tar` + `flate2` + `xz` (no `xz2`, no `async-tar`). | All three crates are MIT/Apache-2.0 with no C dependency. Keeps the Windows / Linux / macOS CI matrix simple and the binary self-contained. `xz2` (with liblzma) is rejected because of the C build dependency. |
| 2026-06-06 | Add German (`de`) as the third localisation. | Exercises a two-form plural rule (similar to Russian), validates the i18n pipeline at three locales, and targets a large EU open-source audience. French, Chinese, and Japanese stay as candidates for later milestones. |
| 2026-06-06 | Defer CLI self-update (`supazip update`) to 1.1. | 1.0 ships without self-modifying code; users update through package managers (Homebrew, winget, scoop, apt, AUR). Removes the only self-modifying attack surface in the CLI binary. `self_update` is still allowed as a dev-dependency for future experimentation. |
| 2026-06-06 | Adopt the long-term 12-month roadmap (0.2.0 → 1.0.0) and file all task tracking through `.github/ISSUE_TEMPLATE/milestone-task.yml`. | Five tracks (Engine, GUI, QA + Security, i18n + a11y + docs, Distribution) with feature-freeze-over-date-freeze policy. The ROADMAP document and the issue template replace ad-hoc planning. |
| 2026-06-06 | Use the `xz` crate (pure-Rust, MIT) for `tar.xz` in 0.2.0. | The roadmap already chose pure-Rust for tar backends; `xz2` would have re-introduced the liblzma C dependency. `xz` is slightly slower but cross-builds cleanly on Windows / Linux / macOS. |
| 2026-06-06 | Hand-roll minimal plural-form logic in 0.2.0; defer `icu_pluralrules` / `fluent` to 0.5. | Three locales with simple plural rules (en/ru/de = 2 forms, ru = 3) do not justify an ICU dependency (+1.5–2 MB binary). Adding `icu_pluralrules` is revisited in 0.5 when the third locale lands and a real ICU locale is requested. |
| 2026-06-06 | Cargo-fuzz in 0.2.0: ship harnesses for list/extract/create × 4 backends; CI runs a 60 s smoke per PR. Long fuzz runs are manual / nightly. | Skeleton-only keeps CI cost linear, the harness count matches the WS-C target (12 targets), and any crash repro is preserved in the corpus. 10-min-per-PR fuzz is moved to 0.4 when MSRV and OS matrix are wider. |
| 2026-06-06 | `cargo publish --dry-run` in 0.2.0; no real crates.io upload. | The user has not provided a crates.io token. Dry-run validates metadata, license files, README rendering, and `cargo doc` while keeping 0.2.0 a GitHub-only release. Real publish is a single follow-up once the token is available. |
| 2026-06-06 | CI OS matrix in 0.2.0 is `windows-latest` + `ubuntu-latest` only; macOS is added in 0.4.0 alongside the wider platform work. | macOS runners are slow and brittle in GitHub Actions; the Rust core is largely portable, and platform-specific issues will surface during 0.3 GUI work anyway. |
| 2026-06-06 | Bump `brotli` from 7 to 8 in `supazip-core/Cargo.toml`. | `brotli 7.0.0` (latest 7.x) contains a `T::AllocatedMemory` pattern that fails to compile on rustc 1.92. API we use (`CompressorWriter`, `BrotliDecompress`) is unchanged between 7 and 8, so this is a non-breaking bump. The plan file `m0.2.0-engine-solid.md` listed `"7"`; the version pin is corrected in this commit. |
| 2026-06-06 | GUI drag-and-drop uses egui's built-in `ctx.input(|i| &i.raw.dropped_files)`. No new dependency. | `rfd` does not support system-level drop, and `egui` already exposes the file paths through its raw input layer. Wayland users get a fallback hint in the status bar; full Wayland support is deferred to 1.1 when `egui` lands stable Wayland DnD. |
| 2026-06-06 | Recent files persist as JSON in `dirs::data_local_dir()/supazip/recent_files.json`, capped at 10 entries. | JSON is human-debuggable and matches the JSON output mode we will ship in 0.4. SQLite is overkill for 10 rows; TOML is human-friendly but slower on rewrite. Limit 10 is the standard "Recent" UX. |
| 2026-06-06 | Progress UI is a modal dialog with a deterministic progress bar (driven by `progress.entries`) and a Cancel button. | Modal blocks the main window so users cannot double-trigger an operation but does not block the event loop. Deterministic bar beats an indeterminate spinner for archives > 1 MB. |
| 2026-06-06 | Menu bar is wired through eframe's `with_menu` API; native on macOS, in-app on Windows / Linux. | This is the cross-platform default; later we can add per-platform accelerators. Pure in-app menu would lose the macOS menubar convention, and a no-menubar layout loses keyboard discoverability. |
| 2026-06-06 | Property tests in 0.3.0 are round-trip invariants only: `create → list → extract → bytes-equal`. One proptest file per backend (5 total). | Round-trip catches 90% of corruption bugs; metadata invariants and path-traversal rejection are already covered by the unit tests in m0.2.0. Full invariant battery is moved to 0.4 when MSRV / OS matrix widens. |
| 2026-06-07 | Hand-rolled runtime plural selection logic; no ICU or Fluent dependency. | Three locales (en/ru/de) have simple 2–3 form plural rules that do not justify an ICU dependency (+1.5 MB binary). A lightweight Rust function `plural_form(locale, n) -> &'static str` + TOML `[key.one]`/`[key.other]` blocks is sufficient. ICU/Fluent are revisited in 1.1 only if a fourth locale with complex rules (e.g., Arabic, Polish) is requested. |
| 2026-06-07 | mdbook documentation is local-only (no GitHub Pages publish). | The user prefers to avoid managing a gh-pages branch and workflow. `mdbook build` + `mdbook serve` for development; docs published as static HTML in `docs/book/` for offline reading. A GitHub Pages deploy job can be added in 1.0-rc.1 if the team decides to host. |
| 2026-06-07 | GUI settings persist as JSON in `dirs::config_local_dir()/supazip/settings.json`. | Matches the pattern already used by recent_files.json. JSON is human-debuggable; TOML is an alternative but adds no benefit for 5–10 key-value pairs. Settings cover: language override, theme (dark-only in 0.5), max archive size, recent files limit. |
| 2026-06-06 | WS-C fuzz skeleton: hand-roll `supazip-core/fuzz/` rather than running `cargo fuzz init`; add a CI `fuzz-smoke` job with matrix `strategy = [smoke, none]` and `continue-on-error: true`. | Local toolchain is `stable 1.92 + 1.92.0` with no nightly and no `cargo-fuzz` crate installed, so `cargo fuzz init` cannot run end-to-end. The `fuzz/Cargo.toml` follows the standard cargo-fuzz book template, the 15 harnesses are split 4 backends × 3 ops (zip, 7z, tar, tar.gz, tar.xz), and the `tar*` harnesses are written to no-op when the WS-B backends are not in the registry yet. The smoke job runs only `zip_list` and `sevenz_extract` for 60 s each — the two backends that existed before 0.2.0 — and is intentionally `continue-on-error: true` so a missing nightly toolchain or a flaky run never blocks the main build. The `none` matrix leg is the explicit off-switch for the initial 0.2.0 cut. |
| 2026-08-17 | Keep a single GitHub identity placeholder `your-org/supazip` until a real repository exists. Do not invent a handle. | Public origin is not configured. Mixing `<owner>`, `your-org`, and `supazip/supazip` made packaging and README lie. One string is replaceable in a single pass later. |
| 2026-08-17 | Treat `PeaZip/` as an ignored nested checkout, not a gitlink. | The folder was mode 160000 without `.gitmodules`, which dirtied `git status`. Design inspiration stays local; it is not part of the build. |
| 2026-08-17 | Design system v2: richer terminal, light theme in 1.1, tokens as runtime. | Keep the 1.0 aesthetic (precise / dense / calm). Tokens 2.0 (`themes.dark` / `themes.light`, `meta.version` 2.0.0) are the contract; GUI consumes them via `Style::from_tokens` in 1.1 (may land in a parallel commit). Light palette is WCAG AA on `#F6F8FA` at the YAML level; GUI re-audit after the mapper ships. Embedded JetBrains Mono and monoline toolbar icons are in 1.1 scope. Archive editor and Material/Aqua stay out. Canon is `DESIGN.md` in place — no `DESIGN-v2.md`. Milestone: `docs/milestones/m1.1.0-design-v2.md`. |
| 2026-08-17 | Harden 1.0.1 before feature-creep / crates.io. | Local `v1.0.0` is not a public release (placeholders, CI/release path issues). Ship 1.0.1 (identity, workflows, completions/man, CHANGELOG, packaging honesty) before design-runtime feature work goes out and before `cargo publish` / `git push` to crates.io. Design v2 code may be prepared in parallel; publication order is harden first. |
